# フル開発フロー

対象: $ARGUMENTS

タスクIDなら `.claude/tasks/` の該当ファイルを読み、状態を `doing` にする。説明文なら先に `/plan` 相当の簡単な分解を行い、タスクファイルを作ってから始める。

1. **作業ブランチ**: `main` 上なら `feature/<タスクID>-<短い名前>` を作って切り替える。
2. **設計確認**: タスクに設計が足りなければ **architect** に確認する。足りていれば省略してよい。
3. **実装**: **developer** に実装を依頼する。lint・型チェック・テストが通るところまで。
4. **テスト**: **tester** にテストの追加と実行を依頼する。プライバシー・安全の観点を必ず含める。
5. **レビュー**: **reviewer** に差分のレビューを依頼する。
6. **修正**: 「必須」の指摘があれば developer に直してもらい、失敗したテストだけ再実行し、再レビューする（最大2周。それでも残ればユーザーに相談）。
7. **記録**:
   - タスクファイルの状態を `review`（PR待ち）にし、作業ログを書く。
   - 新しい設計判断があれば `.claude/decisions.md` に追記する。
   - `.claude/progress.md` を更新する。
8. **報告**: 変更の要約、テスト結果、残った課題、PR を作るかどうかの確認。

push と PR 作成はユーザーの確認を取ってから行う。
